# P1-039 — Configure JDK setup

> Status: In Progress — hosted verification pending

## 1. Goal and context

Establish exact Java parity between WSL and Linux CI. Use the installed reference Oracle JDK 25.0.5.1; no application or Kafka setup.

## 2. Concepts explained in my own words

GITHUB_ENV and GITHUB_PATH make a step output available to later steps; setting a shell variable alone would not persist. A JDK includes compiler and runtime; a runtime-only installation cannot compile.

## 3. Work performed and artifact

Added sudo invocation of existing checksum-pinned Linux installer and fixed-path exports. Reused verify-java.sh to compile/run release 25, inspect class major 69 and reject malformed source plus release 99. Hosted execution pending push.

## 4. Decisions and rationale

Reuse the reviewed artifact and installer instead of adding setup-java vendor/version interpretation and a second download policy. CI is already Linux, so no WSL layer is needed there. Root installation is limited to /opt; probe executes as normal hosted runner. Existing runtime ADR applies.

## 5. Best practices and design patterns

Apply environment parity, checksum fail-closed and reusable verification. Tool bootstrap is pipeline infrastructure; no business pattern applies. Maven lifecycle and JUnit execution remain next tasks.

## 6. Common mistakes, errors and vulnerabilities

Wrong PATH can silently invoke runner-preinstalled Java. Fixed JAVA_HOME, explicit version output and release/class-file checks expose mismatch. Invalid source/release tests must fail as expected; their success would fail the probe. Mutable latest URL can cause availability failure without accepting altered bytes.

## 7. Testing, verification and evidence

Previous installer/checksum source reviewed; source diff inspected. Require actual hosted install and compiler negative/positive probe before completion. This is CLI compiler verification, not JUnit or Kafka integration.

## 8. Debugging and operational notes

For checksum mismatch review upstream release and checksum without disabling TLS. If JAVA_HOME differs inspect step exports and Linux path. Temporary Java probe removes owned files; runner /opt disappears after job.

## 9. Security and SSDLC check

Artifact trust crosses Oracle HTTPS and committed hash. Installer has sudo only for tool placement, no secrets or service listener. Local root-default execution remains disclosed; CI normal-user test success is separate evidence.

## 10. Lessons learned and knowledge checks

Learned: per-step environment needs explicit export channel; identical Linux artifact can serve WSL and hosted CI; compiler class major catches target drift; negative compilation is useful evidence. Still need Maven/runtime integration.
