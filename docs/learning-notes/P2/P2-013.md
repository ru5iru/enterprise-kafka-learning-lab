## 2. Concepts explained in my own words

SLF4J is a facade/API; a runtime provider performs logging. API-only classpath can warn and fall back to NOP, silently dropping application events after startup. Use one compatible application-selected provider, avoiding competing providers or bridge cycles. This exercise uses matching 2.0.20 API/simple artifacts from the existing Boot BOM; it does not override future Boot-managed logging.

{} placeholders defer formatting, not Java argument evaluation. Expensive arguments still execute at disabled levels unless guarded or supplied lazily through a suitable fluent API. Fluent builders need terminal log(). Throwable placement matters: keep it as the exception argument, not merely stringify it and lose cause/stack information. Logging exception text is allowed only when reviewed as safe.

Parameterized text is not sanitization or automatic structured output. CR/LF can forge apparent records; allowlist/validate fields and bound values at actual logging boundaries. MDC delegates to the provider; simple/NOP use no-op context. Thread-local context, where supported, does not automatically follow arbitrary futures/pools and must be copied/restored/cleared deliberately. A logger return does not prove durable audit delivery.

## 5. Best practices and design patterns

Applies facade/provider separation, lazy work and least-data logging. Useful severity, bounded metadata and context ownership matter; the facade itself supplies no security or delivery pattern. Real structured logging, sink saturation/retention and traces remain owning future tasks.

## 6. Common mistakes, errors and vulnerabilities

Multiple providers, bridge loops, payload/exception leakage and stale MDC across worker reuse are reviewed risks, not additional executed tests. No actual redaction control claimed.

## 8. Debugging and operational notes

If expected logs disappear, inspect provider/version/classpath and startup warnings before enabling all TRACE. If an expensive debug call runs, inspect eager arguments. If logs split, inspect CR/LF and sink escaping. For MDC issues inspect provider capability and async lifecycle, not just put() calls. No broad raw environment/config logging for diagnosis.

## 9. Security and SSDLC check

Logs are an export boundary: exclude tokens, payloads, private identifiers and credential-bearing exceptions even at DEBUG. Negative newline and exception messages are synthetic only and inspected in memory. Parameterization is not a sanitization guarantee; MDC is not authentication. No external messaging, secret, open port or new application dependency.
