# Architecture Decision Records

Create an ADR when a task introduces or materially changes a cross-service, architectural, security, delivery or data-ownership choice. Use [0000-template.md](0000-template.md); allocate the next unique number **when the decision is actually made**. No decisions beyond the approved roadmap are asserted by the initial scaffold.

Statuses: `Proposed`, `Accepted`, `Superseded`, `Deprecated`. Reference task IDs and learning notes. Describe alternatives and consequences, not only the selected technology. The baseline choices are documented in `docs/roadmap/ARCHITECTURE.md`.
