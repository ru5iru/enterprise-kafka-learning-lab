## 2. Concepts explained in my own words

A technology inventory is a map of responsibilities and constraints, not a package installation list. Kafka stores and transports events; client libraries express application interaction with that platform; KRaft handles cluster metadata rather than business processing. Supporting infrastructure must be introduced when its learning prerequisite exists, not because it appears in the final architecture diagram.

## 5. Best practices and design patterns

Assign a purpose, phase, and decision status to every technology family. Verify exact supported versions and compatible combinations at the owning ADR/implementation task; never use unreviewed latest tags.

Layered responsibilities separate applications, Kafka control/data plane, persistence/integration, security, observability, and delivery. The inventory describes those layers without creating runtime modules or contracts.

Implementation and production controls remain with their scheduled tasks; this is a planning result, not proof of runtime reliability or proficiency.
