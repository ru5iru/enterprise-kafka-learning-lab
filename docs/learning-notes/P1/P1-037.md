## 1. Goal and context

Create the minimal hosted automation shell for P1. Learn event-to-job execution before adding checkout and build in their own tasks. This is runner readiness, not Kafka or Java validation.

## 2. Concepts explained in my own words

A workflow listens for repository events and creates isolated runner jobs. Read-only contents permission limits the ephemeral token. A concurrency group cancels superseded work on the same ref; different branches remain independent.

## 3. Work performed and artifact

Added .github/workflows/ci.yml with push path filters, unfiltered pull requests, Ubuntu 24.04 x86_64 assertion, 20-minute timeout and explicit bash fail-fast behavior. Real execution is pending the candidate push.

## 4. Decisions and rationale

Use hosted Ubuntu to match WSL Linux architecture without installing WSL in a Linux runner. Restrict push paths to executable inputs to avoid duplicate completion-document builds; PR checks still cover the final aggregate. Avoid pull_request_target and secret-dependent untrusted code. No architecture decision beyond existing Linux-runtime ADR.

## 5. Best practices and design patterns

Apply least privilege, bounded execution and incremental delivery. CI orchestration is a pipeline pattern; no distributed messaging pattern is implemented. Source checkout, toolchain, tests and artifacts deliberately await assigned tasks.

## 6. Common mistakes, errors and vulnerabilities

YAML generation alone cannot establish passing CI. Wrong OS/architecture fails the runner step. Cancelling superseded runs is expected, not a successful test. Fork PRs receive no repository secrets; avoid privileged target events. Branch protection remains separate.
