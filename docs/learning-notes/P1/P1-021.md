## 1. Goal and context

P1-021 ensures Git exists and works natively in WSL after P1-020. The existing installation already satisfies the need, so verification/adoption is preferable to unnecessary replacement.

## 2. Concepts explained in my own words

Git stores objects/refs separately from working files and the index. A clean commit can become a dirty working tree without changing history. Distribution package revisions can carry maintenance beyond the upstream version banner. Windows and Linux Git may operate on one tree, but concurrent mutations risk index/ref races.

## 3. Work performed and artifact

Adopted the current Ubuntu Git package, added a Linux verification script and guide. The actual temporary repo exercise performed init/add/commit, detected a later edit and rejected an invalid ref. Real checkout access was read-only; publication credentials were untouched.

## 4. Decisions and rationale

Keep the existing candidate-matching Ubuntu package rather than replacing it with a new repository/upstream build. Use synthetic per-command identity in an isolated temporary repo, not a global user identity. Alternative: configure Linux remote credentials now; deferred because local tool verification does not require them.

## 5. Best practices and design patterns

Preserve user configuration and source history, isolate test repositories and disable inherited hooks for a synthetic commit. Validate dirty-state/error detection. Resource ownership and traceability apply; no Kafka application pattern is involved.

## 6. Common mistakes, errors and vulnerabilities

Concurrent Windows/WSL writes can corrupt intended staging, global identity changes can misattribute work, and inherited hooks can execute unrelated automation. The probe avoids those paths. It detects a real modified file and rejects a bad ref; remote credential behavior remains unverified.

## 7. Testing, verification and evidence

Actual package/candidate inspection and the executable probe passed. The synthetic commit was never pushed and its temp repository was removed. No real Git history rewrite, global config change or remote authentication test was performed.

## 8. Debugging and operational notes

If Linux cannot read the mounted checkout, inspect ownership/mount/config instead of globally disabling safe-directory checks. For publication, use the established Windows Git path sequentially. The probe restores no real files and cleans only its own temporary repository.

## 9. Security and SSDLC check

The boundary is shared source history and developer identity/credentials. Fake lab@example.invalid is explicitly scoped to disposable test history, not CSV ownership or actual commits. No tokens/configuration were printed or copied between hosts.
