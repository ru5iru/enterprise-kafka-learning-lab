## 1. Goal and context

This task keeps local/generated files out of a Kafka monorepo without hiding the source and evidence needed for reproducible learning. P1-002 is Done and published. No Java module, database or broker state is created by testing path names.

## 2. Concepts explained in my own words

Git ignore patterns affect untracked path discovery. A trailing slash selects a directory, a leading slash anchors to repository root, and an exclamation mark negates an earlier rule. A file already in the index remains tracked even after an ignore rule matches it. Ignore does not inspect content or grant access control.

## 3. Work performed and artifact

Kept existing OS/editor, Maven/Java, Python, PKI and infrastructure exclusions. Added sanitized .env variant examples, local runtime/state and compressed SQL/export exclusions, with warnings about tracked files and broad certificate patterns. Ran CLI probes against path strings only; the probes do not install tools or create fixtures.

## 4. Decisions and rationale

Allow example environment files to remain reviewable while excluding real .env variants. Alternative: ignore every environment example; rejected because onboarding needs sanitized templates later. Retain conservative PEM/ASC exclusion; narrowly allow a reviewed public fixture later rather than enabling every certificate-shaped file now. No ADR is needed for this repository hygiene refinement.

## 5. Best practices and design patterns

Use positive and negative examples to keep a deny-list from swallowing legitimate inputs. Preserve Maven wrapper JAR/scripts and SQL migrations. Prefer narrow state paths over ignoring all SQL or all infrastructure. No application pattern applies; full secret detection is deferred, not simulated by .gitignore.

## 6. Common mistakes, errors and vulnerabilities

The CLI proved 20 unwanted path examples ignored and 12 legitimate path examples visible. Mistakes avoided include ignoring all migration SQL, losing wrapper assets, assuming an example filename sanitizes its content, and assuming tracked secrets disappear. A pattern cannot detect a token embedded in a README; that residual risk remains.

## 7. Testing, verification and evidence

Executed git check-ignore --no-index -q per path and git ls-files -ci --exclude-standard. All 20 positive and 12 negative probes passed; no tracked path currently matches ignore rules. See exact path lists in evidence. No fake secret values or runtime files were generated.

## 8. Debugging and operational notes

Use git check-ignore -v -- path to find the responsible rule. If an exclusion is too broad, narrow it or add a specific non-secret exception. An ignored parent directory may prevent a nested negation from working; test the complete path. Recover policy changes with a new revert/correction, never force-add a credential.

## 9. Security and SSDLC check

Protected assets are local credentials, keys, state and reports; the boundary is working tree to shared history. Broad certificate exclusions are intentional until fixture review. Content review still matters for allowed paths. Revocation/rotation is required after an actual exposure; no such incident is claimed here.

## 10. Lessons learned and knowledge checks

1. Ignored and untracked are different from removed from history.
2. Negative probes protect reproducibility assets.
3. Environment-example naming is not sanitization.
4. Root-anchored runtime paths avoid hiding unrelated source directories.
