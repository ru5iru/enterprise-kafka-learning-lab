## 1. Goal and context

P1-020 proves actual container execution after engine/Compose checks. P1-019 is Done and published. This is a bounded tool probe, not an application or Kafka deployment.

## 2. Concepts explained in my own words

An image digest identifies content; a container is an execution instance with runtime limits and mutable state. An exit status and expected output together establish useful execution. Successful client/API calls alone cannot prove the runtime can start a Linux process.

## 3. Work performed and artifact

Pulled the official test image, recorded its digest, added a restricted repeat/failure/cleanup script and documentation. Two greeting runs succeeded; nonexistent entrypoint and absent local image failed. Verified all captured container IDs were removed; retained the cache without pruning.

## 4. Decisions and rationale

Use a digest after initial publisher resolution and --pull never during the experiment. Alternative: rerun latest without recording identity; rejected because bytes could change. Use unique cidfiles rather than a shared container name so cleanup cannot target unrelated work. ADR-0012 still governs the rootful daemon.

## 5. Best practices and design patterns

Apply no network, read-only filesystem, non-root process, dropped capabilities, no-new-privileges and bounded resources for this simple test. Observe failures and state cleanup. These are local hardening measures, not proof of a production isolation boundary or distributed-service behavior.

## 6. Common mistakes, errors and vulnerabilities

Risks include changing image tags, accidentally pulling a missing image, leaving failed containers and broad cleanup deleting user data. Digest/pull policy, explicit failures and captured-ID cleanup address them. Rootful daemon privilege and image vulnerabilities remain residual risks; no scanner result is invented.

## 7. Testing, verification and evidence

Actual digest acquisition and the script ran in WSL. Two positive executions matched the greeting; invalid entrypoint was rejected, missing image returned 125 and no captured container remained. Evidence links the exact commands/flags and observed output. No broker or application experiment ran.

## 8. Debugging and operational notes

On failure, distinguish image availability, daemon permission, OCI executable failure and assertion/cleanup failure. Use only the probe captured IDs for recovery. Do not chmod the socket, enable TCP or prune global state to force success.

## 9. Security and SSDLC check

Public official image bytes cross the registry boundary and execute under a privileged local daemon, with a restricted container process. No secrets, host bind mounts, ports or persistent volumes are supplied. Digest identity does not establish vulnerability-free code or prevent daemon-level risk.

## 10. Lessons learned and knowledge checks

1. An image is not a running container.
2. Immutable identity and expected output strengthen evidence.
3. --pull never makes the missing-image negative deterministic.
4. Cleanup must own the exact resource ID.
Knowledge check: why keep the cache rather than prune? Avoid unrelated state destruction. Unknown: later service networking/readiness.

## 11. Completion decision and handoff

Acceptance is met by repeated observed execution, expected failures and verified cleanup. Only P1-020 is Done. Publish before P1-021 adopts/verifies Linux Git.
