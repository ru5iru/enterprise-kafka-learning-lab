## 1. Goal and context

P1-030 defines useful safe diagnostics after error handling. P1-029 is Done/published. It is a standard, not an operational logging stack or security-control completion.

## 2. Concepts explained in my own words

Logs describe discrete events with context; metrics aggregate bounded labels; traces require actual context propagation. Parameter placeholders do not sanitize untrusted strings. Async callbacks/thread pools can lose or leak thread-local context unless ownership/cleanup is explicit.

## 3. Work performed and artifact

Added field/level rules, exclusions, injection/length/cardinality guidance, exception-boundary alignment, async-context and sink/retention limits. Reviewed synthetic allowed and rejected output scenarios with primary logging/security references.

## 4. Decisions and rationale

Choose allowlisted bounded structured metadata instead of dumping records/environments and then attempting broad redaction. Use framework-managed logging/provider later rather than competing backends now. Keep a provisional generic ID bound distinct from actual trace formats. Existing observability ADR remains unchanged.

## 5. Best practices and design patterns

Log once at the meaningful handling boundary, separate logs from metrics labels, keep debug exclusions active and require actual output capture before claiming sanitization. Structured observability and context ownership are planned patterns; no propagation/encoder is implemented.

## 6. Common mistakes, errors and vulnerabilities

Raw payloads/headers, credential-bearing causes and CR/LF fields can leak data or forge entries. High-volume retry traces and high-cardinality metrics can exhaust resources. Documentary scenarios reject these patterns, but no runtime redactor/saturation test is claimed.

## 7. Testing, verification and evidence

Executed content/cross-reference review and scenario walkthroughs after reading SLF4J/OWASP guidance. The evidence labels review versus future log-capture tests. No logger/provider, trace pipeline or security scanner ran.

## 8. Debugging and operational notes

For future missing context, inspect async ownership and cleanup instead of inventing trace IDs. For noisy/error logs, check the handling boundary and aggregation. Never attach raw environments/records during troubleshooting; correct policy/config with redacted evidence.

## 9. Security and SSDLC check

The boundary is internal operational context into persistent/public diagnostics. Allowlisting, safe field bounds and exclusions are requirements, not implemented controls. No real payloads, credentials, sink or retention configuration was introduced.

## 10. Lessons learned and knowledge checks

1. Parameterization is not sanitization.
2. Logs, metrics and traces have distinct guarantees.
3. Debug level does not exempt secret hygiene.
4. Thread-local context needs async ownership.
Knowledge check: does logger success prove durable audit storage? No. Unknown: captured runtime output/sink behavior in later tasks.

## 11. Completion decision and handoff

Acceptance is met by reviewed tailored logging standards and limitations. Only P1-030 is Done. Publish before P1-031 defines configuration conventions.
