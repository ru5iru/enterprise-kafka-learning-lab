# P1-042 — Publish CI test artifacts

> Status: In Progress — hosted verification pending

## 1. Goal and context

Publish reviewable hosted test artifacts, retaining useful status without bundling workspace data. This is test evidence retention, not application telemetry.

## 2. Concepts explained in my own words

JUnit XML may contain JVM properties, captured logs and exception messages. Rebuild an allowlisted XML view with suite counters, testcase identity/timing and failure/error/skipped type; discard other content. Artifact storage is a separate trust boundary.

## 3. Work performed and artifact

Upload only target/ci-reports/*.xml, unique run/attempt name, seven-day retention, no hidden files. always condition after successful checkout retains failure reports too. WSL local positive/synthetic-negative checks passed; hosted publication pending.

## 4. Decisions and rationale

Use sanitized JUnit over raw reports to avoid property/output leakage. Retain type/count but omit stack/message; console logs remain available under source logging policy. Warn when no files after early failure rather than replace primary diagnosis; P1-041 report guard still blocks missing suites on a successful build. No third-party reporting service or credential added.

## 5. Best practices and design patterns

Apply data minimization, least privilege and bounded retention. Artifact publication is pipeline evidence, no Kafka pattern. Supply-chain attestation and durable audit storage are deferred; source evidence links outlast short artifact retention.

## 6. Common mistakes, errors and vulnerabilities

Uploading all target/workspace can expose credentials/caches. Narrow path and reconstructed XML reduce scope. Synthetic sensitive marker was removed from properties/output/exception body while failure status survived. Test names/types can themselves contain data; current fixed tooling names are reviewed, future parameterized tests need care.

## 7. Testing, verification and evidence

WSL prepared two real reports. Synthetic failure report retained type/count while marker was absent; empty report tree returned zero files. Hosted upload must succeed and artifact metadata/content be inspected before Done; no publication result inferred from YAML alone.

## 8. Debugging and operational notes

If no artifact appears, inspect setup/build outcome before widening paths. Parent directories are created for early-failure preparation; no reports is reported as zero. Artifacts expire after seven days; committed evidence records run IDs and sanitized observations.

## 9. Security and SSDLC check

Contents-read token, pinned action revision and no secrets. Artifact allowlist excludes .m2, environment and raw system output. This reduces leakage but does not certify arbitrary future test names or console logs. No external notifications sent.

## 10. Lessons learned and knowledge checks

Learned: test reports are data exports; XML reconstruction can preserve status without payloads; retention affects evidence availability; failed builds still need diagnostics. Next verify actual CI failure reporting with a controlled failure.
