## 1. Goal and context

P1-035 integrates previously proven formatter/lint into a real build after P1-034 tests. It must reject defects and restore a usable local verify before hosted CI work.

## 2. Concepts explained in my own words

Formatter layout, AST-style checks, compiler diagnostics, dependency convergence and runtime tests cover different defect classes. Their management/configuration must be activated in a lifecycle. Plugin adapters can expose options differently from a standalone CLI; repository mirrors control actual resolution separately from inherited POM declarations.

## 3. Work performed and artifact

Activated Spotless/Checkstyle in child validate, added focused style rules and dependency convergence, constrained repositories with project settings, added negative-gate script and editor Verify build task, and updated docs. Fixed real AOSP import drift and inherited-repository certificate warning using documented configuration, then observed full passing checks.

## 4. Decisions and rationale

Keep the same formatter version/style with explicit AOSP reorder option rather than changing source/pins to hide adapter drift. Choose small reviewable AST rules and retain compiler lint. Use an HTTPS Central mirror instead of disabling TLS or trusting an unexpected inherited repository. Existing ADR-0013 governs pins/scope; no business architecture change occurs.

## 5. Best practices and design patterns

Fail early on formatting/style defects, verify expected diagnostic categories, protect existing source from probe overwrite and restore a clean full build. Separate quality coverage from security assurance. Immutable pins and constrained resolution improve reproducibility but do not prove vulnerability absence.

## 6. Common mistakes, errors and vulnerabilities

Actual failures exposed mismatched import-order defaults and an inherited expired-certificate endpoint. Both were diagnosed/corrected without ignoring checks. The negative fixture proves bad layout and broad catch rejection. Current plugin Unsafe deprecation and default-root local execution remain explicit limitations.

## 7. Testing, verification and evidence

Initial failed/passing builds, the controlled quality-negative script and final editor-task verify were executed. Actual Checkstyle zero-violation and 1+1 passing test reports are checked. No hosted CI or full security scan is claimed from these local results.

## 8. Debugging and operational notes

For drift, compare CLI/adapter options before mass-reformatting. For repository errors, inspect effective resolution/provenance rather than disabling TLS. For rule false positives, review a narrow justified mechanism instead of blanket suppression. The script removes only its generated fixture and restores verify.

## 9. Security and SSDLC check

Network artifact resolution is constrained by project-only HTTPS mirror settings, no credential/CA changes. AST IllegalCatch covers configured spellings, not full semantic/security analysis. Local WSL UID 0 was observed and disclosed; no user/group privilege change or unprivileged execution is claimed.

## 10. Lessons learned and knowledge checks

1. Same tool version does not guarantee adapter-option parity.
2. Transitive plugin metadata can introduce repositories.
3. Quality tools have distinct coverage and warnings.
4. Execution context must be observed, not assumed.
Knowledge check: did zero Checkstyle errors prove secret safety? No. Unknown: hosted runner behavior and future tool/JDK upgrades.

## 11. Completion decision and handoff

Acceptance is met by activated real gates, observed negative failures/corrections and restored full WSL verify through the editor task. Only P1-035 is Done. Publish before P1-036 defines the consolidated review checklist.
