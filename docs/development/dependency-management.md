# Maven dependency management

[ADR-0013](../architecture/decisions/0013-p1-build-verification.md) records the exact source-reviewed build/BOM pins and the tooling-probe scope. Use Boot's 4.2.0 BOM for managed project libraries, narrow explicit dependency declarations/scopes and explicit active plugin versions. Importing a BOM does not add libraries; pluginManagement does not execute goals. The root parent/aggregator must preserve independent future service builds and data ownership.

Use test scope for JUnit/test-only tools, avoid unnecessary production transitives, and inspect effective POM/dependency tree for each module. Do not use systemPath/local user JARs, dynamic LATEST/RELEASE/ranges, unreviewed upstream SNAPSHOTs or arbitrary additional repositories. The unreleased project's own source version may be 0.1.0-SNAPSHOT; that is distinct from fetching mutable remote dependencies. Keep credentials in reviewed external settings/secret injection, never POMs/command lines/log dumps. Use HTTPS and strict checksums; do not disable checks because a mirror/network fails.

Treat BOM overrides, exclusions, new repositories and major plugin changes as reviewed compatibility/security decisions with a reason, exact pin and actual regression evidence. Do not override Spring/Kafka/JDBC versions speculatively. Plugin-internal dependencies, such as the chosen Checkstyle engine, have a different classloader/management scope than application dependencies and require their own verified pin.

P1-033 introduces the minimal parent/tool probe; P1-034 wires tests; P1-035 wires quality gates; later CI tasks prove hosted behavior. P2 still owns the real Spring starter and pinned Maven wrapper. A configured plugin or zero-test green build is not proof that any Java/test executed. This policy is document review plus actual publisher metadata/BOM availability, not a completed dependency scan or full compatibility matrix. [Evidence](../testing/evidence/P1-032-review.md) records the review. Rollback of a future dependency change requires restoring the reviewed pin and rerunning affected build/test/contract checks, not deleting user caches blindly.
