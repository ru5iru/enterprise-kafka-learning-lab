## 1. Goal and context

A PR template helps a reviewer assess a task without relying on chat history. P1-008 is Done and pushed. This task updates the existing default template; it does not submit a PR, request reviewers or merge the P1 work.

## 2. Concepts explained in my own words

The template populates an editable PR body after it is present on the default branch. Its checkboxes are author statements, not test execution or enforced merge conditions. A base/head identifies the exact diff and a verification row distinguishes expected behavior from actual observation.

## 3. Work performed and artifact

Reworked the template around concrete before/after behavior, design trade-offs, base/head and authorized package scope, actual verification/CI state, disclosed self-review, task docs/CSV, risks/rollback and final merge conditions. Added explicit repository URLs so copied body links keep a stable context.

## 4. Decisions and rationale

Keep one default Markdown template in .github to avoid competing discovery locations. Alternative: multiple change-type templates; rejected because task type and N/A reasons already support this lab without extra navigation. Blank prompts/unchecked boxes avoid pre-asserting success. No architecture ADR is needed.

## 5. Best practices and design patterns

Require reproducible commands and evidence instead of vague tests-passed prose. Make planned versus executed and self versus independent review explicit. Include rollback and final-head review. This is review evidence capture, not an application pattern; platform enforcement is deferred.

## 6. Common mistakes, errors and vulnerabilities

Prechecked boxes can imply imaginary success, and a template can hide missing evidence if every test is simply called N/A. The wording requires a reason and applicable gaps. GitHub cannot infer truth from a body; manual review remains necessary. Relative links in copied bodies were avoided using the P1-008 lesson.

## 7. Testing, verification and evidence

Static checks found one default template, seven required sections and nine unchecked confirmations. Checked explicit Not run/N/A/no-CI states, negative-case coverage, merge authorization and repository URL prefixes. Self-reviewed documentation and missing-evidence scenarios; no GitHub autofill or live PR test ran.

## 8. Debugging and operational notes

If new PRs do not receive this body, confirm default-branch merge and supported path/case, then check for competing templates. An existing PR body does not prove a new template was discovered. Restore/correct with a new commit rather than rewriting historical PR evidence.

## 9. Security and SSDLC check

Public PR bodies can leak credentials or real payloads, so the leading instruction and security-policy link prohibit that input. No mentions, reviewer assignments or notifications were added. A checked security box is a review statement, not a secret scanner result.

## 10. Lessons learned and knowledge checks

1. Checkboxes record claims, not execution.
2. Base/head commits bound review scope.
3. A skipped applicable test is different from N/A.
4. A template activates on default-branch publication, not merely topic push.
Knowledge check: how should a docs-only change report CI when no workflow exists? Not configured. Unknown: rendered autofill until merge.
